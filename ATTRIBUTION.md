# Attribution & provenance

The Qurʾān is a sacred trust (_amāna_). Every external source this project
consumes — whether **bundled** in the repo or **fetched at runtime** — is
recorded here with its owner, licence, and how we use it. These notices **must
travel with any copy or derivative**: it is both a licensing requirement and an
amāna.

> **The rule:** we only **bundle/redistribute** data that carries a licence
> permitting it (CC-BY, MIT, Apache-2.0, public domain, or explicit written
> permission). Data that is _displayed but not redistributable_ is fetched from
> its original source **at runtime** and is **not** stored in this repo.
> Attribution **accompanies** a valid licence — it does not replace one.

This file is the repo-wide index. Per-dataset detail (required notices, ingest
steps) lives in [`packages/data/ATTRIBUTION.md`](packages/data/ATTRIBUTION.md).

## Adding a new source — checklist

Whenever the project starts consuming a **new** external source, do all of this
in the same change (CI and review expect it):

1. **Find the licence** from a primary source (the repo's `LICENSE`, the data
   file's header, or the provider's terms). _Unstated ≠ permitted_ — absence of a
   licence means **all rights reserved**.
2. **Decide bundle vs. runtime:**
   - Licence permits redistribution (CC-BY/CC0/MIT/Apache/PD, or written
     permission) → may be **bundled** (`datasets/` via `ingest.ts`).
   - Otherwise → **runtime fetch from the original source only**; never commit it.
3. **Check AGPL-3.0 compatibility** for anything bundled (no NonCommercial, no
   NoDerivatives; GPL/CC-BY-SA need care and stay under their own terms).
4. **Record it here** (the right section) **and** in
   `packages/data/ATTRIBUTION.md` if it is a dataset. Attribution must travel
   with the data.
5. **Islamic content** (meanings, tafsir, gradings) is tagged
   `needs-scholar-review` before any production launch.
